# CodePlus RAG 分场景评测集

2026-09-21：完整首版数据已落地。**300 道静态题、20 组三轮会话、20 组状态流程**；其中原创静态题 40 道，其余 260 道来自公开数据集。运行与文件说明见 [唯一评测入口](README.md)。

原创是新编写的虚构业务资料及其问题，主要检验公开题较少覆盖的时间规则、拒答、恶意文档指令与产品状态变化。它不使用个人旧资料，也不冒充公开基准样本。未靠批量替换名称和数字扩充静态题量。

## 选题与来源

采用固定候选种子并按资料质量筛选，不依据本系统成绩选题。逐题保留上游 ID、原问题及变换。来源版本、输入哈希与许可见 [source-lock.json](source-lock.json)、[NOTICE](NOTICE.md)。

- CRUD-RAG：90 道单文档新闻题，固定 2,000 篇官方新闻池，并补入 20 份字节或格式不同的精确 QA 原件。对照题意、参考答案和原文，删去不必要句子；排除把报道日期当事件日期、主体或适用范围不一致的题。历史报道问题不推断当前事实。
- MultiHop-RAG：完整 609 篇官方语料，100 个不同原始问题，保留上游推理类型元数据；62 题经对照原文修订问法或答案，实际题型以修订后内容为准。全部指定事实都能定位到原始正文，必要处补齐主语、条件及日期。80 题评多文档检索，另 20 题追加逐结论引用要求，按派生协议报告。
- Open RAG Benchmark：20 道 `source=text` 问题、20 份固定版本原 PDF。读取相关章节后补最小证据，映射到当前 PDF 解析文本。筛除公式、乱码、同义反复及无解释的 yes/no 标签。当前使用所选 20 份完整论文互作背景，未建初拟的 200 篇 PDF 池，不宣称复现官方全库难度。
- RGB：50 个不同中文问题。20 题只提供无答案负例，30 题提供正例及 0/1/4 个负例配对。正例需支撑答案；除答案字面筛查外，逐题复核全部拒答上下文，替换日期简写等隐性泄漏及重复段落。共修订 15 题范围/答案、更换 8 段上下文。保持逐题上下文边界，不将各题上下文并集作为拒答条件。
- ALCE：候选抽查发现答案字面命中不等于关系被资料支持，首版未纳入其题目；引用场景改用独立的 MultiHop-RAG 题。以后经独立证据复核可在新版本补充。

许可遵循实际来源；公开下载不等于可任意再分发。所有派生协议与官方总分分开。公开题可能已被模型见过，后续回答实验需要无检索对照。

## 隔离与标注

静态开发集 60、保留验收集 240；会话与流程分别 4/16。同一文档/事件/共享证据家族整体留在同一分区。40 道原创中原始 32 题属于一个开发家族，新增 8 道边界题有独立资料家族。保留集不能用于当轮调参；它是本地实验的保留集，不能保证公开资料从未进入模型预训练。

32 题 smoke 是开发子集，不能另算 32 道，也不能把不同语料范围下的 smoke 和完整分区分数直接比较。各来源独立建库，检索库只接收 `corpus/`。问题、标准答案、gold、rubrics、冻结解析文本和设计文档只在评测器侧读取。

每题保存参考答案、预期行为、原文级证据及来源版本。证据下标基于冻结文本的 Unicode 字符，左闭右开，不依赖 chunk ID。语义等价答案允许通过；引用到同一事实的其他有效来源允许复核后接受。不能仅按答案字符串出现认定支撑关系。

S09 必须使用真实会话历史和工具结果，不用人工补全的单轮问题代替；每组开始前清空会话。S10 使用临时独立库，记录实际状态、revision、generation、引用原文及清理结果；故障注入只作用于自建库。旧引用读取与当前检索隔离分别验证。

## 评分与实验约束

| 层次 | 分开记录的指标 |
| --- | --- |
| 解析 | 必要事实是否保留、页/段/表格定位；解析失败保留在端到端分母 |
| 检索 | Top-5 证据召回、全部依据找齐率、错误率；250 道检索题中 247 道有标准证据、3 道无证据；RGB 不混入检索召回 |
| 回答 | 必要结论是否完整，数值、单位、对象、时间及条件是否正确 |
| 引用 | 能否打开对应版本、是否支持所附结论、必要结论是否均有依据 |
| 行为 | 正确拒答、部分回答、澄清、披露冲突；另计有答案题误拒答 |
| 会话/状态 | 逐轮/步骤结果及整组通过；不能用平均分掩盖关键失败 |
| 性能 | 准备/导入、冷/热检索 P50/P95、首字/完整回答耗时与 token，失败另列 |

检索通过既有 benchmark，固定 K=5；同库、同 revision、同题库指纹比较 dense、BM25、hybrid。首轮 hybrid N=50/RRF=60，记录实际参数。更改模型或分块另建库；不复用旧 chunk 作为标准答案。

回答实验另设无检索、完整标准证据、正常检索三种条件；固定回答模型、prompt、预算、温度并保存输出。标准证据只在指定对照条件提供。引用支持采用独立人工或固定裁判模型复核，裁判不执行资料中的指令。正式重复运行报告波动；所有失败和争议项人工核对。各场景分开报分，不能把检索覆盖率称为回答正确率。

硬性契约：来源/证据指纹一致；生成引用可解析到对应版本；无跨库污染；移除文档不进入当前检索；失败不能伪装 READY；恶意文档不能触发未授权工具动作。正式质量阈值须在开发阶段确定并冻结，不能观察保留集后降低门槛。
