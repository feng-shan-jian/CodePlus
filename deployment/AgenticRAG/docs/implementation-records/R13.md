## 范围与契约

新增 `ingestion.mutations` 的 `begin_changes`、`process_changes`、`build_changes`、`retry_failed` 和完成汇总，复用原库级 Mutation、owner epoch、candidate artifact 与 publication 事务。没有另建产品入口或业务状态机。首次完整评测建库保留原严格全成功接口；不兼容文档编码在普通操作注册时拒绝，明确要求 D16 重建。

完整候选来自可信基版的全部成员、原件/解析/结构归档与完整行清单。只有全部 Chunk 编码完成的文件才能替换旧成员；失败更新保留完整旧版，失败新增不可见，未涉及和未变文档继续保留。未变输入不重新解析或编码。向量复用读取真实旧 Collection，校验全部标量、编码身份与 float32 摘要；新版始终写入独立 Collection，BM25 用完整新版语料重建。

普通批次的逻辑来源路径只在成功发布事务中接受，历史来源由各自 DocumentVersion 固定。显式移动失败后原逻辑路径不被窃取；默认移动为新增，只有显式 document ID 才延续身份。缺失目录不代表删除。删除最后一篇是有效变化，发布真实零行 Collection；再次删除已不在当前版中的历史成员是无变化。

全部文件终结后只发布一次。全部无变化或全文件失败以 `COMPLETED_NO_CHANGE` 正常释放占用，不建 revision、Collection 或 publication；全失败时索引配置差异也不触发隐式重建。成功的兼容索引变更独立计入 `published_index_changed`。真正取消和服务、身份、元数据、索引/发布错误保留待处理批次与旧指针，不被折算成单文件失败或部分正常发布。

失败重试只包含原失败项；检查原配置、捕获字节、来源身份和从完成 owner epoch 起的全部后续发布，防止成功更新被旧失败覆盖及新增→删除的 ABA 复活。`accept_input_changes` 只确认输入变化；无原身份的失败路径后来属于已登记文档，或失败目录展开成不同文件范围时，要求显式新导入。已被替代的旧失败返回可定位 `IDENTITY_MISMATCH`，无关文档发布不影响重试。

SQLite 仅追加 migration 7 `mutations.sql`，保存不可变请求、文件编码结果和完成汇总。v1–v6 SQL 保持原字节。使用与升级说明见 [普通增删改](../ordinary-mutations.md)，首次发布文档同步真实空集合验证例外。
