## 实现与调用链

报告仍由现有 `codeplus.agent.Agent` 的两条循环执行，使用 report 预算和结构化 Markdown 提示；检索模式仍独立选择 fixed/auto。中文问题要求保留实体、时间、否定、比较约束，由同一回答模型生成英文 query，中文回答并保留英文原文引文。没有报告 Agent、翻译模型、章节工作流或后台续研。

整份答案经现有引用校验后产生不可变 `ValidatedArtifact`，宿主创建专用写调用，通过原 `_execute_tool` / `_execute_tool_noninteractive` 的实际权限路径，调用原 `WriteFile` 和宿主 `FileStateCache`。该写能力不进入模型的知识工具注册表；模型不能用它写未校验草稿或选择目标路径。TUI 保留宿主原 registry/file history，路径检查、ask/deny、读取后覆盖、过期缓存和实际 I/O 错误沿用原规则。

`RunOutcome` 兼容追加 `run_id/save/research`，`HostRunContext` 追加原请求，事件与调用方同步。保存结果单独返回路径、实际字节 SHA-256 和大小；逻辑 Markdown 摘要保持原契约。Windows 多行文件的 CRLF 字节摘要可以与逻辑正文 UTF-8 摘要不同，回读按文本换行验证正文，再按实际字节验证文件。写成后若截止或取消，保存仍为 saved，整体保持 incomplete/cancelled；不能倒退成“没有保存”，也不能误报 completed。

继续研究复用 `Catalog.start_current_run(parent_run_id=...)` 与 `host_runs.detail` JSON，原子绑定开始时最新发布版和新的 QA/report 预算，不新增表或迁移。新轮 registry、evidence 和送达凭证从空开始；同版也重新 search/open。历史引用仍可通过已有归档回看，但不恢复为新轮证据。目标路径不得复用任何祖先报告路径。

公开进度保留目标、顺序用户请求、covered/pending/findings/revised/unverified、来源元数据和停止原因。读取祖先链承接历史线索，失败的中间轮不会抹去较早进度；省略可选 progress 的有效答案使用已公开答案作为待核承接文本，剥离旧引用标记，不复制工具正文/送达 sidecar。所有历史发现明确待核。实际用户请求和中间新增实体、时间、否定约束进入不可静默丢弃的任务文本；发现线索仍可按窗口裁剪。逐轮版本、预算、状态、保存结果、用量和累积用量可查，未知 token 保持未知。
