# R18 实现与执行验证

基线 `1fd01183f9ce914e022d923debc13553b0f71d27`，分支 `codex/rag`。本记录是执行者交接；独立验收与精确本地提交由 Leader 完成。执行者没有 stage、commit 或 push。

## 已实现

`RetrievalSearch` 在三路召回/RRF 后，按稳定 ID 去重并截取冻结的 `rerank_candidates`，使用原始 Chunk 的 canonical 正文及归档 `ChunkInput.index_title` 逐条评分。精排前不拼邻块；实际 FrozenTokenizer 计入 query、标题、模板与特殊 token，再按条数和 padded-token 限制拆批。全部批次的身份、唯一 ID、实际 token 和排序校验通过后，才合并为分数降序、ID 升序的完整排名。超长或任一批次失败均明确失败，无未精排降级，旧确认正文仍可引用。

模型请求复用原 reader、handle、`wait_finished` 和 run pin 生命周期；仅把既有 query 请求接点提取为共用路径并增加 Rerank 调用。整个检索与重排处于原外层 reader 保护区间。客户端断开、取消或结果异常均不被当作 GPU 完成回执。没有增加调度器、Agent 或宿主状态机。

Context 采用 `query-relative-v1` 试验规则：当前 query 相关性排名优先，以组首分数绝对值的 2% 形成近似组，在组内优先未选择文档，保持原始排名且不设来源配额。只减去同文档版本在宿主当前 `evidence_windows` 与本次结果中的重叠 Unicode 区间；不同位置及冲突材料仍可选择。同一响应内、尚未 retain 为宿主窗口的连续 search 不被历史候选抑制，原 pending reservations 与多轮累计预算仍生效。装不下时按 canonical 区间折半裁剪，再经过原完整工具序列化计量。

`evidence_windows` 表示宿主当前保留的原文位置，可由 `retain_prepared_window` 在 HTTP 发送前同步；not_sent/unknown 不自动回滚该窗口。窗口去重与 `delivered_evidence` 的确认交付资格分别管理，不能将保留窗口解释为模型已经看过，也不能将所有 not_sent 解释为没有窗口映射。

`trace.rerank` 保存完整输入 hash/token、批次、实际评分和耗时；`trace.context` 保存所选/裁剪/省略区间、选择前窗口、用量及试验规则。交付 receipt 记录实际请求移出区间，以及只在 compact 确认后生效的清空范围；失败 compact 不宣称已移除。沿用 schema11 JSON，历史十一份 SQL 均不变。固定三路可开启 Rerank，BM25+Rerank 不编码 query，纯 BM25 仍零模型连接；原 DenseSearch、SourceSession 的 `dense=` 和 query-only 工具兼容。

## 正式测试与真实服务

测量 wheel SHA256 为 `85a4c952ba76020d3ba70a02681e4897654fb94763d32301ca8c2d8fb0cea6fc`。测试使用私有常规复制 core/cuda 环境的实际 site-packages，未重装 R17 环境。受影响完整回归的原始结果为 **316 passed / 1 failed，736.29 秒**。唯一失败为收集测试后才更新的打包固定集合缺 `retrieval/context.py`；修正清单后，打包及 Context 评测必要复验 **4 passed，26.85 秒**。两次结果分别保留，不合称一次全绿。

全部模型测量和离线评分结束后，同步模块 README 的当前 Rerank 能力说明，另建最终 wheel `c0e3bf40e5650b78c405f87455bd7b1f3a98a5948bc6ccda3c1918f5c0dee476`。两个 wheel 仅 `METADATA` 与 `RECORD` 变化；72 个生产 Python/SQL/JSON 资源在源码、测量包、最终包和最终安装的 core/cuda 环境逐字节相同，实际加载模块路径与字节也已核对。原测量包和报告保留，未为元数据变化重跑模型或完整回归。

先前定向失败涉及 fixture 的 Span schema 字段、未形成重叠的短正文、实际 padded-token 批数、完成线程与 pin settle 的观察时机，以及测试用了旧安装版本的区间移除日志。它们均保留原始日志，正式回归已覆盖当前修正。没有为满足 fixture 更改 R09/R15 的 pin/GC 生产语义。初次完整回归命令另把现有 `test_evidence_citations.py` 写为不存在的 `test_evidence.py`，零项运行退出4；更正路径后才进行上述实际回归。

两条原 Agent 循环均用实际 SDK 序列化和 SourceTool 执行“首次正文被宿主裁剪、相同 query 再检索、取得未可见尾部、按实际 wire span 引用”的正式用例。当前窗口/历史资格、部分送达、compact 的确认/未知/未发送状态另有 SourceSession/Gateway 用例，原三协议完整窗口与 compact 集成测试继续复用。回答网络为受控 MockTransport，不作为真实回答模型质量证据。

评测失败用例明确区分成功排名后的 Context 故障与检索自身失败：前者保留排名并返回非 PASS；失败的 prepare 不留下有效送达回执。离线测试验证 Context 失败留在正文覆盖分母、失败检索的已耗时间/尝试批次不归零，未知 request/host 上界不混入均值。

真实 GPU/Milvus 专属驱动已通过：3 条原始 Chunk 分 3 批真实 Rerank，BM25 无 query Embedding；真实 tokenizer 超限时未发起模型评分。第二批到达实际 `inference_started` 后关闭认证客户端，得到 `WORKER_UNAVAILABLE`，完整排名和新候选均未提交，旧引用可保存。报错时 `finished_at_error=false` 且 pin 仍 active，随后由实际 `worker_process_death` 完成回执证明结束并释放 pin。该驱动的初次失败为等待了不存在的 `executing` phase，原失败保留，不计为模型失败。

本阶段在私有 Milvus 上真实建立 609 篇、4041 个 Chunk 的发布版本 `8854b0ec-a779-4568-81c5-2380ad7eb7b0`。模型 revision、512/64 分块、COSINE IVF_FLAT/nlist64、原生 BM25、k1=1.2/b=0.75 沿冻结配置。

## 对照口径与已知限制

固定 Hybrid、相同 200 题顺序、TopK10、177 题检索分母，Dense/BM25 候选各 50、Rerank 候选 50、RRF k=60、nprobe64。每题的一次真实检索同时提供排名与生产 SourceSession 选择；以固定工具结果请求模板实际执行 prepare/retain，然后记为 not_sent。没有运行回答模型或人工确认送达。

`selected` 与 `prepared` 分别统计正文片段、上界量、重复及原文区间覆盖。工具正文插入完整 JSON 后的转义扩张可能令最终窗口超过本次试验的 8000 上界；此时排名成功仍保留，Context 明确失败，prepared 为空并以零覆盖留在 177 题正文分母。2 题 smoke 中已观察到 8019 > 8000 的实际拒绝。没有修改单组预算、添加猜测余量或把失败算通过；R19/R23 继续承接完整预算行为及参数冻结。本轮不代表答案正确率、泛化或质量达标。

原 `full-off` 与受影响回归存在并发，保留为诊断与质量证据，不使用其延迟与安静 on 比较。正式成本只采用回归及必要复验结束后的安静组；固定配置、包和输入保持相同，实际执行顺序与时间戳在原始索引记录。
