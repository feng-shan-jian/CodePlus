## 已实现

`inspect_model_switch` 展示单库期望编码、实际编码、基准与目标并持久保存提议。空选择不执行；确认必须仍对应该库、基准和目标。正常 `KnowledgePolicy.start` 接入此检查，并通过 `Catalog.start_current_run` 在运行冻结与 pin 的同一事务中选择当前版本的实际 Embedding 对象，同时保留本次预算、检索设置和 Rerank。

批准、原始归档检查点和既有修改批次同事务登记。重建、发布、失败恢复、放弃与 GC 复用原入口，原件删除后仍从全部归档成员重建；暂时缺失的已登记归档修复后可在同批次继续。公开首次导入和同编码低层发布契约保持，已发布空库允许零成员重建。新增 schema10 只保存提议选择与已有批次关联，前九份 SQL 不变。

失败保留旧 current，`retry` 继续批准目标和原批次；`keep_original` 复用放弃路径并记住该目标，重启不再提示。运行中的批次不提供重试选项。单改 Rerank 不重建，新运行冻结新身份。服务调用与状态见 [模型切换服务](../model-switching.md)。
