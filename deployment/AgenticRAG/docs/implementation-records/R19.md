# R19 实现与执行验证

基线 `cef8821a78447e5dde418cb1d68c6ac73c81fdc7`，分支 `codex/rag`。本记录为执行者交接；独立验收与精确本地提交由 Leader 完成。没有 stage、commit、push 或新建 worktree。真实 `-p` 的正常回答验收仍受官方提供方余额阻塞，不能把本记录解释为 R19 已完成独立验收。

## 实现

`KnowledgePolicy` 复用 `RunOverride`、`resolve_run` 与 `start_current_run`，以可选 keyword 接通 `task_kind='qa'|'report'`、`mode='fixed'|'auto'`。显式模式优先于功能配置，再到 auto 默认值；模式来源在配置重建之前读取实际输入字段集合，最终值及 explicit/configured/defaults、任务类型和预算写入现有 `host_runs.frozen`。显式值与默认值相同仍保留 explicit。旧调用默认 qa，旧 `RunConfiguration` JSON、指纹和 schema11 均不变。

用户入口为 `-p --knowledge-library ... --knowledge-mode fixed|auto` 与 `/knowledge ask --mode fixed|auto ...`，旧调用保持可用，宿主 `--mode` 仍只表示权限模式。实际 `_run_prompt` 构造的 Agent 遇到知识库 ask 权限时返回 DENY；没有交互输入不能自动同意。普通非知识库路径保持原行为。

fixed 注册 query-only search，允许改写、多轮搜索及 open，每次仍执行冻结路线和重排设置。auto 仅增加 strategy 与严格 bool rerank；未传值恢复冻结基础配置，不继承上一轮。核心 `RetrievalSearch` 和 `SourceSession` 同样校验模式权限，当前调用使用局部配置，服务共享 route 不变。禁止模型控制候选数、模型、库、版本、融合参数或预算。

错误返回原阶段、错误码、请求/调用 ID、可用后续动作和选择；重试或改选必须是新显式工具调用。失败和后续调用都有原 trace，`preceding_call_id` 只表示同 run 的上一搜索调用，不推断因果重试关系。成功为空、能力不可用、执行失败分别记录；失败中间排名不会创建可引用候选。auto 的错误说明明确要求重试同一选择时再次传值；省略选项使用基础配置。没有自动回退或增加预算。

QA/report 预算分别解析并贯通 reserve、lease、SourceSession、deadline 和账本。沿用 policy 初始化前置时钟、真实 HTTP 预留/结算、缓存与 unknown 用量、探索后有界收尾、一次引用修正及真实取消/reader 完成。没有另起计时器、模型循环或预算系统。report 在本项只接通预算，报告保存/继续研究仍属 R20。

## 完整请求与分页

R18 的 8000 上界在完整 JSON 转义后曾出现 8019，以及正式组 8018–8243 的拒绝；原始记录不改写。本项在两条现有 Agent 循环 compact/通知之后、SDK stream 之前，复用最终 serializer 和工具 schema 测量完整请求并裁剪正文，再保留独立真实 raw-body 门。没有固定猜测余量、提高单组预算或在 permit 中修改 bytes。

裁剪只使用当前消息中可信 sidecar 覆盖的正文和原工具的纯元数据，已有 spill 预览可再次裁剪，不读取落盘全文或归档补回未发送正文。`returned_spans` 与实际正文同步；发生截取时删除过期 lines。最小完整请求装不下时仍明确停止，不能伪造 confirmed。

open 正文被裁后，从实际尾部签发续读 cursor；原 cursor 是 previous_cursor 时，续读上界仍保留其原业务范围。合法显式翻页复用 `SourceSession.open(..., before_read=...)`，在既有调用次数/时间/累计预算受理及来源/cursor 校验之后移出对应上一页 tool pair，保留当前调用和同消息其他结果。prepared/not_sent 仅同步当前保留窗口，不产生模型调用或 confirmed，不退还累计用量；读取仍失败时恢复旧页供有界收尾。历史已确认引用资格保持，新页只有实际送达后才生效。
