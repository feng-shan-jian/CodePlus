## 真实 GPU 观察

最终双宿主 PID 46308 / 45316 从同一干净 direct-wheel 环境启动；共享实际 worker PID 20600，创建身份 `134345249048128575`，instance `7fa55938-0af6-4c3b-b333-3f9e7424317e`，model UUID `6ed25a52-cfb2-4f2f-9214-9da3098bbd0f`，load_count=1。两配置只改显示名称仍复用。先退出 46308 后 45316 继续使用同模型 UUID，两个宿主 exit 0，最后 worker idle 退出。报告另含实际 module_path、代码摘要、GPU UUID 和各配置，非仅凭磁盘 cache 判断复用。

文档/query 向量保持请求和 item 顺序，1024 维、有限 float32、L2 norm 误差 <1e-4；Rerank 候选 ID 对齐、softmax([no,yes])[yes]，按分数降序及 ID 升序。实际验证四项文档批次、标题/EOS、query instruction、完整 rerank 模板、模型切换，以及 2×2048=4096 padded 边界；超长输入显式拒绝，无 truncate。相同实际 profile 复用；不同实际 profile 切换后实例 UUID/load_count 变化，弱引用证明旧对象不再存活。

运行中取消与 deadline 由实际第一个 decoder 层完成后的 `inference_started` 事件门控，不以 sleep 猜测。取消得到 CANCELLED/completed_batch，cancel_ack=true，随后 worker_finished_notice；deadline 的 result 在 client_wait 返回 DEADLINE_EXCEEDED，随后等待到真实完成通知，未返回迟到成功。队列满/排队取消另有实际 worker 证据和协议 owner 越界测试。

32 MiB allocator 限额在自有 worker 引发真实加载 OOM，返回阶段 load，单槽卸载；测得 allocated 8.125 MiB、reserved 20 MiB、旧模型引用数 0，其他 owner 随后重载成功（load_count=3）。此为受控真实 OOM，不是耗尽共享显存。

通信断开后原 handle 保留 unknown，即便另一个 client 成功也不伪造完成。实际死亡试验只对已认证、位于任务私有目录且 PID/创建身份核验一致的 worker 44804 执行结束；handle 通过 worker_process_death 闭合，随后 stale 重启得到新实例。设备不可用用自有目标进程的空 CUDA_VISIBLE_DEVICES 实际触发；缺依赖用 core 目标解释器实际触发；已有 worker 对不同 runtime 和设备映射显式拒绝。无 CPU/API fallback。

异常完成证据分两层：`worker_fault_helper.py` 用受控 engine/serve 替身验证生产 scheduler/main 在真实子进程传播 fatal、不发 finished；`worker_gpu_fault_helper.py` 在实际模型层/CUDA 排入工作后注入 Python 异常，验证异常返回前 CUDA event 已完成，并在受控同步失败时验证实际进程非零退出。最终 forward 子进程 43140 exit 0，fatal 子进程 43172 exit 1，两者均已退出。这些不能称为自然驱动故障或完整 IPC fatal 端到端实测。
