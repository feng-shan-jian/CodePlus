## 实现

共享 `/knowledge` parser/handler 服务 TUI、原 `-p` 和已有 Remote。管理适配器只编排 Catalog、ingestion、recovery、model_switch 和 citations 的既有业务 API；新增 Catalog 库列表、发布来源和指定版本查询，无 SQL/schema 变更。覆盖创建/选择/关闭、导入/来源/状态、原文身份更新、删除、失败重试、批次恢复/放弃、模型 confirm/retry/keep_original 及历史引用回看。研究 `continue` 保持 R20 语义。

初次重建明确 confirm；失败后需 retry；重复 confirm 不重试；keep_original 保留旧发布版并按其冻结编码继续普通导入。恢复选择实际 OwnerToken，活跃 owner 和模型 BUILDING 显示忙，已结束的 WAITING_RECOVERY 才提示选择。没有终端、空答复、取消不授权执行。

同步修改在适配器线程内取得并持有真实 owner，cancelled 传至普通构建、严格重建和恢复。外层 await 取消只请求线程停止，重复取消继续等待实际线程、GPU handle 和 backend 结束；TUI/Remote 在此之前仍忙。取消与发布竞态时保留真实 receipt 和 operation_status，整体状态单独记录 cancelled。

`-p` 的知识退出码：completed 0、partial/incomplete 2、waiting_confirmation 3、failed 1、cancelled 130。已进入 scope 的 HTTP/工具异常按持久化 RunOutcome 输出 run_id/status/stop_reason；只有未产生 run 的启动异常使用安全的 startup_error。普通任务退出语义不变。

Remote 复用既有 Agent、流事件和权限系统，知识任务独立 Conversation，aclosing 关闭真实流。发起连接取消/断连才取消它的任务，旁观连接断开无影响。权限完成发 `permission_resolved {id, reason}`，明确 answered 与 cancelled；已有 Web handler 按 perm-id 关闭失效弹窗。`command_done` 在真实任务收束后发送，LoopComplete 使用原事件 total_turns 且仅一次。会话只新增 rag_library_id/rag_last_run_id；旧 knowledge/knowledge_binding 不复活。
