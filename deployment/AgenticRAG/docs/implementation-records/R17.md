## 已实现

`RetrievalSearch` 共享原 DenseSearch 的冻结运行、不可变索引、reader/GC 和 canonical source 映射，按显式固定路线执行 Dense、Milvus 原生 BM25 或 Hybrid。Hybrid 的两路共用一个 reader 区间、同一 query 和 Collection，不在两路之间解析 current。BM25 无需模型 provider，不编码 query、不连接 worker；原 DenseSearch 保持显式 Dense 及 `limit` 的原候选上限语义。

核心 RRF 按稳定 Chunk ID 合并，每路只取第一次出现的原始 1-based rank，计算 `sum(1/(rrf_k+rank))`；缺席不贡献，同分按 ID 排序。原始两路分数不混加。完整 trace 保存冻结身份、实际候选上限、各路原候选/分数/排名、完整融合顺序与耗时，可独立复算。

SourceSession 通过新增 schema11 `retrieval_traces` 表按原 `call_id` 保存成功和失败诊断，继续使用既有候选、交付回执和引用路径。合法空分支可以融合；任一路失败整次明确失败，不产生新候选或送达证据，已确认正文仍可引用。正常 KnowledgePolicy 最小接入显式 fixed 三路及 query-only SourceTool，没有另造宿主 Agent 流程。API 和边界见 [检索说明](../retrieval.md)。
